# Offix на Windows-сервере: как устроено и как развернуть

Документ для того, кто обслуживает сервер компании. Скрипты — в `deploy/windows/`.

---

## 1. Почему сайт «жил своей жизнью»

| # | Что было | Как проявлялось | Что сделано |
|---|----------|-----------------|-------------|
| 1 | Сайт отдавал **dev-сервер Vite** (`npm run dev`, порт 5173) — инструмент для разработки, не для людей | «работает только в Хроме / только в Яндексе», белый экран, долгая загрузка. Dev-сервер отдаёт сотни отдельных несжатых файлов и кеширует «оптимизированные зависимости» — у разных браузеров кеш расходится, и страница ломается | Сайт собирается (`npm run build`) и раздаётся **самим сервером Node**: несколько сжатых файлов, кеш браузера настроен правильно |
| 2 | Два адреса и два процесса: `web.offixcrm.ru` → Vite, `offixcrm.ru` → API | Vite пересылал на API только `/api`: файлы (`/uploads`) и сообщения в реальном времени (`/socket.io`) на сайте не работали, адрес аватаров был зашит в код | Оба адреса ведут в **один процесс**: страницы, API, файлы и сокеты — с одного адреса |
| 3 | Сервер и сайт запускались вручную в окнах | «кто-то запускает, кто-то нет»: закрыли окно / перезагрузили компьютер — сайта нет | Сервер — **служба Windows**: стартует с системой, перезапускается при падении, пишет журнал |
| 4 | Весь трафик идёт **через Cloudflare** (туннель) | «с одних Wi-Fi работает, с других нет, с мобильного — то так, то так, с VPN — работает». Часть российских провайдеров ограничивает соединения с Cloudflare: маленькие ответы проходят, большие (файлы сайта) обрываются | Код тут не поможет — это сеть. Ниже два варианта; для пользователей в России надёжнее **вариант А** (прямой HTTPS) |
| 5 | `JWT_SECRET` со знаком `#` | после смены ключа «всех выкинуло», вход не работает: всё после `#` считается комментарием, ключ обрезается | Скрипт установки проверяет ключ; образец генерации — в `server/.env.example` |

> Объяснение «это был кеш DNS на роутере» и «помог `protocol: http2`» — скорее
> совпадение: перезапуск туннеля на время меняет маршрут, но причины 1–4 остаются.

## 2. Как устроено теперь

```
Браузер / приложение ──HTTPS──► [вариант А: Caddy на 443]  или  [вариант Б: Cloudflare → cloudflared]
                                              │
                                              ▼
                              Node (служба «Offix», 127.0.0.1:5000)
                              ├─ /            сайт (web\dist, собранный)
                              ├─ /api/*       API
                              ├─ /socket.io/* сообщения в реальном времени
                              └─ /uploads/*   файлы (с проверкой доступа)
                                              │
                                              ▼
                                   PostgreSQL (127.0.0.1:5432)
```

- Порт **5173 больше не нужен**. Порт 5000 слушает только `127.0.0.1` (`HOST=127.0.0.1`) — снаружи к нему не попасть в обход прокси.
- Мобильное приложение ходит на `https://offixcrm.ru` — для него ничего не меняется.
- Журнал сервера — `C:\mesNation\logs\server.log` (JSON, ротация по 20 МБ). У каждого запроса есть `X-Request-Id`.

## 3. Переход на новую схему (один раз)

Ниже `C:\mesNation` — папка с репозиторием. Все команды — в PowerShell **от имени администратора**.

### 3.1. Резервная копия — до любых изменений

```powershell
cd C:\mesNation
git pull
powershell -ExecutionPolicy Bypass -File deploy\windows\backup.ps1 -BackupDir D:\offix-backup
```

(Если диска D: нет — любой другой путь, лучше не на системном диске.)

### 3.2. Программы

- **Node.js 22 LTS** (`node -v` → v22.x). Если стоит 20 — обновить.
- **NSSM** (управляет службой): `winget install NSSM.NSSM`, затем открыть новое окно PowerShell.
- Git и PostgreSQL уже есть.

### 3.3. Настройки `server\.env`

Сравните с `server\.env.example` и проверьте:

```
NODE_ENV=production
PORT=5000
HOST=127.0.0.1
WEB_DIST_DIR=../web/dist
TRUST_PROXY=loopback
```

`JWT_SECRET` — 32+ символа, **только буквы и цифры**. Если в нём есть `#` или он короткий, сгенерируйте новый (все пользователи один раз войдут заново):

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Если пароль БД простой (слово + год и т. п.) — смените его в PostgreSQL (`ALTER USER ... PASSWORD '...'`) и в `DB_PASSWORD`.

### 3.4. Остановить старые ручные запуски

Закройте окна, где запущены `npm run dev` (и в `server`, и в `web`). Если они в автозагрузке или в планировщике — удалите оттуда.

### 3.5. Служба и первая сборка

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\install-service.ps1 -StopOldProcesses
powershell -ExecutionPolicy Bypass -File deploy\windows\update.ps1 -SkipPull
```

Второй скрипт соберёт сайт и сервер, запустит службу и дождётся ответа `/api/health`.
Проверка на самом сервере: открыть в браузере `http://127.0.0.1:5000` — должен открыться сайт.

### 3.6. Доступ из интернета — выберите вариант

#### Вариант А (рекомендуется): прямой HTTPS на белом IP

Подходит, если у сервера есть постоянный внешний IP и на роутере можно пробросить порты.
Трафик идёт напрямую, без Cloudflare — пропадают обрывы у российских провайдеров.

1. **Роутер**: пробросить TCP **80** и **443** на `192.168.1.51` (адрес сервера в сети). Порты 5000 и 5432 **не** пробрасывать.
2. **Брандмауэр Windows**:
   ```powershell
   New-NetFirewallRule -DisplayName "Offix HTTPS" -Direction Inbound -Protocol TCP -LocalPort 80,443 -Action Allow
   ```
3. **Caddy** (веб-сервер с автоматическими сертификатами): скачать `caddy.exe` с caddyserver.com в `C:\caddy`, скопировать `deploy\windows\Caddyfile.example` в `C:\caddy\Caddyfile`, поправить email. Зарегистрировать службой:
   ```powershell
   nssm install Caddy C:\caddy\caddy.exe run --config C:\caddy\Caddyfile
   nssm set Caddy AppDirectory C:\caddy
   nssm start Caddy
   ```
4. **DNS в Cloudflare**: записи `offixcrm.ru` и `web.offixcrm.ru` — тип **A**, значение — внешний IP сервера, облачко **серое** («DNS only»). Запись туннеля (CNAME на `...cfargotunnel.com`) удалить. Службу `cloudflared` после проверки остановить.
5. Через 5–10 минут: `https://offixcrm.ru` открывается, замок в адресной строке есть (сертификат выпустил Caddy).

Если провайдер не даёт пробросить 80/443 или IP меняется — вариант Б.

#### Вариант Б: оставить туннель Cloudflare

Скопировать `deploy\windows\cloudflared-config.example.yml` в `C:\cloudflared\config.yml` (подставить UUID туннеля). Главное — **оба** адреса ведут на `http://127.0.0.1:5000`:

```yaml
ingress:
  - hostname: offixcrm.ru
    service: http://127.0.0.1:5000
  - hostname: web.offixcrm.ru
    service: http://127.0.0.1:5000
  - service: http_status:404
```

Перезапустить: `Restart-Service cloudflared`. Сайт станет заметно стабильнее (причины 1–3 устранены), но проблема 4 (провайдеры и Cloudflare) остаётся.

### 3.7. Ежедневная резервная копия

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\backup.ps1 -BackupDir D:\offix-backup -Register
```

Каждый день в 03:30: дамп базы (хранится 30 дней) и копия всех загруженных файлов.

### 3.8. Проверка

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\diagnose.ps1
```

Всё зелёное — готово. Красное — пришлите вывод целиком.

## 4. Обновление и откат

```powershell
powershell -ExecutionPolicy Bypass -File C:\mesNation\deploy\windows\update.ps1
```

Скрипт получает изменения из `main`, собирает сайт и сервер в отдельные папки, останавливает службу на несколько секунд, подменяет версию, запускает и проверяет. Открытые у людей вкладки со старой версией продолжают работать до обновления страницы.

Если после обновления что-то сломалось:

```powershell
powershell -ExecutionPolicy Bypass -File C:\mesNation\deploy\windows\rollback.ps1
```

Миграции базы применяются автоматически при старте сервера и пишутся так, чтобы откат кода не требовал отката базы.

## 5. «У кого-то не открывается» — что собрать

1. С сервера: вывод `diagnose.ps1`.
2. С устройства, где не открывается (и с того, где открывается — для сравнения):
   - открыть `https://offixcrm.ru/api/health` — пришёл ли текст `{"status":"ok",...}`;
   - открыть главную; если белый экран — F12 → вкладка «Сеть» (Network) → скриншот красных строк;
   - сеть: Wi-Fi (какой провайдер) / мобильный (какой оператор) / VPN;
   - в командной строке: `nslookup offixcrm.ru` — какой адрес вернулся.
3. Время, когда не открывалось (по журналу сервера можно найти запросы).

Если `/api/health` открывается, а главная — нет, и это зависит от провайдера: почти наверняка ограничение Cloudflare (причина 4) → вариант А.

## 6. Безопасность сервера — чек-лист

- Наружу открыты только 80/443 (вариант А) или ничего (вариант Б, туннель изнутри наружу).
- PostgreSQL слушает только `127.0.0.1`; пароль БД длинный и случайный.
- `server\.env` и `C:\cloudflared\creds\` — не в git, доступ только администраторам.
- Резервные копии идут каждый день; раз в месяц проверяйте, что последняя копия восстанавливается: `pg_restore -l файл.dump`.
- Обновления Windows и Node.js LTS — регулярно.
