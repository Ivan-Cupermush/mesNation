# Статистика и KPI: файл KPI и ежедневные отчёты о продажах

Всё ниже есть и на сайте, и в мобильном приложении («Статистика» → «+» или
кнопки в блоке KPI; экраны `KpiImport`, `KpiRule`, `KpiClients`).

## Откуда что берётся

| Что | Источник |
|---|---|
| Квадратики «Выручка», «АКБ», «В среднем за день», «Продано, шт» | отчёт о продажах из 1С за месяц |
| Цели, назначенные вручную «по отчёту о продажах» | отчёт о продажах |
| Показатели KPI: факт, % выполнения, «к выплате» | файл KPI (загружают ежедневно или еженедельно) |
| Цели, которые ведутся вручную | сотрудник или руководитель отмечает выполнение |

1. **Файл KPI сотрудника** — загружает руководитель (своим подчинённым),
   директор или тот, кому включена функция «Загрузка файлов KPI». Сотрудник
   себе файл не загружает. Сначала показывается, что найдено в файле:
   сотрудник (по имени в файле), месяц (по дате в ячейке A2), показатели.
   Повторная загрузка за тот же месяц заменяет показатели из файла: цели,
   созданные вручную, и поправленные правила выплат остаются.
   - Факт, процент выполнения и «к выплате» берутся из файла; отчёты о продажах
     их не меняют.
   - Позиции с галочками и крестиками (V / X): выполнено столько позиций,
     сколько галочек.
   - Позиции без отметок: если в таблице «да» — выполнение берётся из строки
     «% выполнения», если «нет» — не выполнено.
   - ГСМ не учитывается и не показывается.
   - Прогноз у KPI из файла — только выполнение в процентах при текущем темпе
     (для сумм продаж). Темп и прогнозы считаются по рабочим дням (пн–сб).
2. **Отчёт о продажах из 1С** («Валовая прибыль», клиент → «По менеджерам»)
   — каждый день. Подходят оба варианта:
   - с 1-го числа по сегодня — каждый новый отчёт заменяет прежний;
   - за один день — дни складываются.

   Отчёт, который частично пересекается с уже загруженным, отклоняется:
   иначе продажи посчитались бы дважды. Ошибочный отчёт можно удалить в истории
   загрузок — продажи и цели по отчёту пересчитаются без него.

## Квадратики

| Квадратик | Как считается |
|---|---|
| Выручка | сумма продаж сотрудника с 1-го числа по последний отчёт |
| АКБ | клиенты с продажами; «Есть повод» не считаются, задвоенные (список «Задвоенные») — одна точка |
| В среднем за рабочий день | выручка ÷ рабочих дней (пн–сб, воскресенье — выходной) с 1-го числа по последний отчёт |
| Продано, шт | количество по всем товарам |

## Цели по отчёту о продажах

Руководитель при назначении цели включает «Считать по отчёту о продажах»
(по умолчанию включено): факт — продажи товара или группы с таким названием
(«Балтика Стаут», «Сидр»). Тип цели задаёт, что считать: рубли — сумма,
штуки — количество, контракты — точки, купившие товар. Правило можно уточнить:
меню «⋯» у цели → «Правило расчёта» (товар, группы товаров, клиенты, позиции).

Выплата по умолчанию — из названия показателя: «порог 90%, при выполнении 80–90%
кэф 0,5» → от 90% — бонус, 80–90% — половина; «Порог 200 000 руб» и строка «%»
со ставкой → процент от продаж. До итогового файла выплату можно поправить там же.

**Списки клиентов** («Статистика» → «+» → «Клиенты «Есть повод»»): сеть
«Есть повод» и задвоенные клиенты. Можно вставить списком, загрузить из Excel
или отметить клиентов из отчётов (подсвечены те, кто покупал товары
«ЕстьПовод»). Строка списка — часть названия: «ИП Соколов Д.И.» — все его точки.

**Менеджеры из 1С** находятся среди сотрудников по имени в любом порядке
(«Мишина Анастасия» = «Анастасия Мишина», ё = е). Кого не нашли — в результате
загрузки и на странице импорта есть кнопка «Выбрать сотрудника»; выбор
запоминается для следующих отчётов.

## Месяцы

Сотрудник видит свою статистику и KPI за текущий месяц. Руководитель и директор
переключают месяцы на странице сотрудника (директор — и у себя).

## Функции сотрудников

| Функция | По должности |
|---|---|
| Загрузка отчётов о продажах (и списки клиентов, сопоставление менеджеров) | директор, руководители |
| Загрузка файлов KPI | директор, руководители |
| Назначение KPI вручную (и правила расчёта) | директор, руководители |
| Управление базой знаний | директор, руководители |

Руководитель включает или отключает функции своим подчинённым, директор — всем:
при создании сотрудника и потом в профиле сотрудника («Функции»). Включить
можно только ту функцию, которая есть у самого руководителя. Включённая
директором функция действует на всю компанию (например, оператор загружает
отчёты за всех), руководителем отдела — на его отдел. Свой KPI сотрудник
не создаёт и не загружает (кроме директора).

## Стартовая страница

«Главная» — первая вкладка: приветствие по времени суток и напутствие (каждый
раз новое), 4 квадратика продаж, до трёх показателей KPI с наименьшим
выполнением («Обратите внимание») и задачи на сегодня: срок сегодня или уже
прошёл, а также те, что в работе.

## API (для мобильного приложения)

- `GET /api/home?tz_offset=&prev=` — стартовая страница: `greeting`, `name`,
  `phrase {id, text}`, `stats`, `kpi {count, totals, focus[]}`, `tasks[]`.
- `GET /api/kpi/month?user=<id>&month=ГГГГ-ММ` — KPI за месяц: `targets[]`
  (у каждой цели `calc`: `source`, `now`, `forecast`, `forecastPercent`, `max`,
  `marks`, `rule`, `condition`, `hint`, `items`), `totals`, `stats` (квадратики),
  `coverage`, `canSwitchMonth`, `canEdit`, `can {reports, kpiFile, assign}`.
  Свой KPI — всегда за текущий месяц.
- `GET /api/kpi/people?for=kpi_files|kpi_assign|sales_reports` — кому можно
  применить функцию.
- `GET /api/kpi/sales/subordinates` — у сотрудника `sales` (квадратики за месяц).
- `POST /api/kpi/sales/targets/assign` — дополнительно `from_report: true` или
  `fact_rule`.
- `GET/PUT /api/users/:id/permissions` — функции сотрудника
  (`{ permissions: { kpi_files: true, sales_reports: null } }`, null — по должности);
  `POST /api/role-tree/users` принимает `permissions`; `/api/auth/me` отдаёт `permissions`.
- `POST /api/kpi/sales/import-report` (multipart `file`) — отчёт о продажах.
- `POST /api/kpi/import` (multipart `file`, `dryRun=1` — только разобрать;
  иначе `userId`, `month=ГГГГ-ММ`) — файл KPI.
- `GET/POST/DELETE /api/kpi/client-lists`, `POST /api/kpi/client-lists/import`,
  `GET /api/kpi/report-clients?month=`, `GET /api/kpi/report-groups?month=`.
- `GET /api/kpi/reports?month=`, `DELETE /api/kpi/reports/:id`,
  `GET /api/kpi/reports/unmatched`, `GET/POST/DELETE /api/kpi/reports/aliases`.
- `PATCH /api/kpi/sales/targets/:id` — дополнительно `fact_rule`, `payout_rule`,
  `bonus_amount`.

Код: `server/src/services/kpi/` (разбор файлов, правила, пересчёт),
`server/src/services/permissions.ts` (функции), тесты —
`server/tests/kpi.test.ts` (файлы в формате заказчика с вымышленными данными).

## Задачи

Принятые задачи через 3 дня после выполнения уходят в архив автоматически
(раз в час, `server/src/services/taskArchive.ts`); в истории задачи это видно как
«Автоматически». Из архива задачу можно вернуть. «Наблюдаю» показывает все
задачи, где вы наблюдатель (и созданные вами), «Команда» — все задачи
подчинённых, в том числе те, где вы тоже участник.
