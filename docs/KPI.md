# KPI: файл KPI и ежедневные отчёты о продажах

## Как это работает

1. **Файл KPI сотрудника** (раз в месяц, руководитель) — план, бонусы и правила
   выплат по каждому показателю. Сайт: «Статистика» → «+» → «Загрузить файл KPI»
   (или кнопка «Файл KPI» в блоке KPI сотрудника). Сначала показывается, что
   найдено в файле: сотрудник (по имени в файле), месяц (по дате в ячейке A2),
   показатели и правила. Повторная загрузка за тот же месяц заменяет только
   показатели из файла: цели, созданные вручную, и поправленные правила остаются.
   Итоговый файл в конце месяца (с колонкой «к выплате») показывается как
   «по итоговому файлу».
2. **Отчёт о продажах из 1С** («Валовая прибыль», клиент → «По менеджерам»)
   — каждый день. Сайт: «+» → «Загрузить отчёт о продажах». Подходят оба варианта:
   - с 1-го числа по сегодня — каждый новый отчёт заменяет прежний;
   - за один день — дни складываются.

   Отчёт, который частично пересекается с уже загруженным, отклоняется:
   иначе продажи посчитались бы дважды. Ошибочный отчёт можно удалить в истории
   загрузок — факт пересчитается без него.
3. После каждого отчёта факт всех показателей команды за месяц пересчитывается,
   а в карточке показываются: «заработано сейчас», «прогноз на конец месяца»
   (если продажи пойдут в том же темпе), пороги на полосе и что сделать
   для следующего порога.

## Как считается факт

| Показатель (по названию) | Факт из отчёта |
|---|---|
| План продаж без ЕП | выручка клиентов, которых нет в списке «Есть повод» |
| Продажи «Есть повод» (и с опечаткой «Есть Подод») | выручка клиентов из списка «Есть повод» |
| План Балтика | выручка в группах товаров со словом «Балтика» |
| План ОПХ | выручка в группах Heineken / ОПХ |
| АКБ | число клиентов с продажами; «Есть повод» не считаются, задвоенные (из названия показателя и списка) — одна точка |
| Дистра (позиции «Балтика Стаут кег — 1 ТТ») | сколько разных точек купили каждую позицию; названия сравниваются нечётко («Стаут» = «Stout») |
| Оклад, ГСМ | фиксированная выплата |
| Любой другой | если слово из названия есть в группе товаров отчёта («План Сидр» → «СИДР, МЕДОВУХА») — выручка этих групп, иначе вручную |

Выплата по умолчанию — из названия показателя: «порог 90%, при выполнении 80–90%
кэф 0,5» → от 90% — бонус, 80–90% — половина; «Порог 200 000 руб» и строка «%»
со ставкой → процент от продаж. Правило любого показателя руководитель может
поправить: меню «⋯» у показателя → «Правило расчёта» (группы товаров, клиенты,
пороги, коэффициенты, ставка).

**Списки клиентов** («Статистика» → «+» → «Клиенты «Есть повод»»): сеть
«Есть повод» и задвоенные клиенты. Можно вставить списком, загрузить из Excel
или отметить клиентов из отчётов (подсвечены те, кто покупал товары
«ЕстьПовод»). Строка списка — часть названия: «ИП Соколов Д.И.» — все его точки.

**Менеджеры из 1С** находятся среди сотрудников по имени в любом порядке
(«Мишина Анастасия» = «Анастасия Мишина», ё = е). Кого не нашли — в результате
загрузки и на странице импорта есть кнопка «Выбрать сотрудника»; выбор
запоминается для следующих отчётов.

## Права

Загружать отчёты и файлы KPI, править правила и списки — руководитель (свои
подчинённые) и директор (все). Сотрудник видит свой KPI.

## API (для мобильного приложения)

- `GET /api/kpi/month?user=<id>&month=ГГГГ-ММ` — KPI за месяц: `targets[]`
  (у каждой цели `calc`: `now`, `forecast`, `forecastPercent`, `max`, `marks`,
  `rule`, `hint`, `items`), `totals` (`now`, `forecast`, `max`, `fixed`, `file`),
  `coverage` (`asOf` — по какое число есть отчёты, `elapsed`, `days`),
  `canEdit`, `canUpload`.
- `GET /api/kpi/sales/summary` и `/employee/:id/stats` — у целей тоже есть `calc`.
- `POST /api/kpi/sales/import-report` (multipart `file`) — отчёт о продажах.
- `POST /api/kpi/import` (multipart `file`, `dryRun=1` — только разобрать;
  иначе `userId`, `month=ГГГГ-ММ`) — файл KPI.
- `GET/POST/DELETE /api/kpi/client-lists`, `POST /api/kpi/client-lists/import`,
  `GET /api/kpi/report-clients?month=`, `GET /api/kpi/report-groups?month=`.
- `GET /api/kpi/reports?month=`, `DELETE /api/kpi/reports/:id`,
  `GET /api/kpi/reports/unmatched`, `GET/POST/DELETE /api/kpi/reports/aliases`.
- `PATCH /api/kpi/sales/targets/:id` — дополнительно `fact_rule`, `payout_rule`,
  `bonus_amount`.

Код: `server/src/services/kpi/` (разбор файлов, правила, пересчёт), тесты —
`server/tests/kpi.test.ts` (файлы в формате заказчика с вымышленными данными).
