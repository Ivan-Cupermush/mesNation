# Offix через VPS: пошаговый план

Сервер Offix остаётся в офисе (Windows, Томск). Снаружи пользователи попадают
на VPS в Selectel, а VPS передаёт запросы в офис по туннелю, который офис
открывает сам.

```
Телефоны и браузеры ─HTTPS─► VPS Selectel (Caddy: сертификаты, страница «сервер недоступен»)
                                   │ 127.0.0.1:15000
                                   ▲ SSH-туннель — офис подключается сам (исходящее соединение, порт 22)
                             Windows-сервер в офисе: служба OffixTunnel ─► служба Offix (127.0.0.1:5000)
```

- **В офисе не открывается ни один входящий порт**, внешний IP офиса нигде не публикуется.
  Атака на сайт бьёт по VPS, корпоративная сеть не страдает.
- **На VPS нет данных**: база, файлы и сам сервер остаются в офисе.
- **Туннель Cloudflare не удаляем** — он остаётся запасным путём (часть 7).

Где запускать команды:

| Значок | Где |
|---|---|
| 💻 | ваш компьютер с Linux (там, где склонирован репозиторий) |
| 🌐 | VPS, после `ssh root@<IP>` |
| 🪟 | Windows-сервер в офисе, **PowerShell от имени администратора** |

Везде ниже `<IP>` — внешний IP VPS.

---

## Часть 0. SSH-ключ на вашем компьютере (один раз)

💻
```bash
ls ~/.ssh/id_ed25519.pub 2>/dev/null || ssh-keygen -t ed25519 -C "offix-admin"
cat ~/.ssh/id_ed25519.pub
```
Последняя команда печатает строку `ssh-ed25519 AAAA...` — она понадобится при создании сервера.
Закрытый ключ (`~/.ssh/id_ed25519`) никому не передавайте.

## Часть 1. Сервер в Selectel

Облачный сервер:
- регион — **Москва** (или Санкт-Петербург, если пинг из Томска до него меньше);
- образ — **Ubuntu 24.04 LTS**;
- 1 vCPU, 2 ГБ памяти, диск 25 ГБ;
- **публичный IP-адрес** — обязательно (без него сервер виден только внутри Selectel);
- SSH-ключ — вставьте строку из части 0.

Запишите внешний IP. Проверьте вход:

💻
```bash
ssh root@<IP>
```
(Если Selectel создал пользователя не `root`, войдите под ним и дальше пишите `sudo` перед командами 🌐.)

## Часть 2. Настройка VPS (около 3 минут)

💻 Скопировать скрипт на VPS (из папки репозитория, ветка с этими файлами):
```bash
cd ~/mesNation
git pull
scp deploy/vps/setup.sh root@<IP>:/root/
```

🌐 Запустить:
```bash
bash /root/setup.sh --domains "test.offixcrm.ru" --email admin@offixcrm.ru
```

Что делает скрипт: обновления безопасности (ставятся сами), брандмауэр (открыты только 22, 80, 443),
вход по SSH только по ключу, защита от перебора паролей, Caddy с автоматическими сертификатами,
отдельный пользователь для туннеля, которому разрешено только одно — открыть порт 127.0.0.1:15000.

В конце скрипт печатает **IP** и **готовую команду для Windows** вида
`...install-tunnel.ps1 -VpsHost <IP> -HostKey "ssh-ed25519 AAAA..."` — сохраните её.

> ⚠️ Не закрывайте текущую SSH-сессию, пока не проверите, что входите заново из **второго** окна:
> 💻 `ssh root@<IP>`. Вход по паролю скрипт выключает, остаётся только ключ.

## Часть 3. DNS для тестового адреса

Cloudflare → домен `offixcrm.ru` → **DNS** → **Add record**:
- Type: **A**
- Name: **test**
- IPv4 address: **<IP>**
- Proxy status: **DNS only** (серое облачко)

Через 1–5 минут проверка:

💻
```bash
dig +short test.offixcrm.ru          # должен показать <IP>
curl -sI https://test.offixcrm.ru | head -1
```
Ответ `HTTP/2 503` — **это правильно**: HTTPS работает, сертификат выпущен, просто офис ещё
не подключён (в браузере будет страница «Сервер компании временно недоступен»).

## Часть 4. Windows-сервер в офисе

### 4.1. Новая версия Offix службой Windows (если ещё не сделано)

Подробно — в `docs/DEPLOY.md`, разделы 3.1–3.5. Кратко:

🪟
```powershell
cd C:\mesNation
git pull
powershell -ExecutionPolicy Bypass -File deploy\windows\backup.ps1 -BackupDir D:\offix-backup
winget install NSSM.NSSM          # затем открыть НОВОЕ окно PowerShell (администратор)
powershell -ExecutionPolicy Bypass -File deploy\windows\install-service.ps1 -StopOldProcesses
powershell -ExecutionPolicy Bypass -File deploy\windows\update.ps1 -SkipPull
```
Проверка: на самом сервере открыть `http://127.0.0.1:5000` — открывается сайт.

### 4.2. Туннель

🪟 Вставить команду, которую напечатал `setup.sh` (часть 2), например:
```powershell
powershell -ExecutionPolicy Bypass -File C:\mesNation\deploy\windows\install-tunnel.ps1 -VpsHost <IP> -HostKey "ssh-ed25519 AAAA..."
```
Скрипт создаст ключ офиса и напечатает команду `sudo offix-allow-office '...'`.

🌐 Выполнить эту команду на VPS (целиком, с кавычками).

🪟 Вернуться в окно PowerShell и нажать **Enter**. Скрипт проверит вход и запустит службу `OffixTunnel`.

🌐 Проверка:
```bash
sudo offix-status
```
Должно быть: `туннель подключён` и ответ `{"status":"ok",...}`.

Теперь `https://test.offixcrm.ru` открывает сайт — уже через VPS.

## Часть 5. Замер: VPS против Cloudflare

Запускать с разных сетей: офис, дом, **ноутбук через раздачу с телефона** (мобильный интернет разных операторов).

💻 Linux:
```bash
bash deploy/measure/measure.sh https://offixcrm.ru https://test.offixcrm.ru
```
🪟 Windows:
```powershell
powershell -ExecutionPolicy Bypass -File deploy\measure\measure.ps1 https://offixcrm.ru https://test.offixcrm.ru
```
Пришлите таблицы — по ним решаем, переключать ли основные адреса. Смотрим на «Всего»
и, главное, на «Ошибок»: у Cloudflare на проблемных сетях обычно бывают ошибки и большой разброс.

## Часть 6. Переключение основных адресов

1. **Запишите текущие записи** `offixcrm.ru` и `web.offixcrm.ru` в Cloudflare (тип и значение,
   обычно CNAME на `...cfargotunnel.com`, оранжевое облачко) — они нужны для отката.
2. Cloudflare → DNS: у `offixcrm.ru` и `web` поменять запись на **A → <IP>**, облачко **серое**.
3. 🌐 Добавить домены в Caddy:
   ```bash
   bash /root/setup.sh --domains "offixcrm.ru web.offixcrm.ru test.offixcrm.ru" --email admin@offixcrm.ru
   ```
4. Через 1–5 минут проверить в браузере `https://offixcrm.ru` и вход в мобильном приложении
   (оно ходит на `https://offixcrm.ru` — менять в нём ничего не нужно).
5. 🪟 Туннель Cloudflare оставить установленным, но выключить:
   ```powershell
   Stop-Service cloudflared
   Set-Service cloudflared -StartupType Manual
   ```

## Часть 7. Откат на Cloudflare (если что-то пошло не так)

1. 🪟 `Start-Service cloudflared`
2. Cloudflare → DNS: вернуть записи из шага 6.1 (CNAME на туннель, оранжевое облачко).

Через 1–5 минут всё снова идёт через Cloudflare. VPS при этом не мешает — его можно не трогать.

## Часть 8. Обслуживание

| Что | Где | Команда |
|---|---|---|
| Состояние входа и туннеля | 🌐 | `sudo offix-status` |
| Журнал Caddy | 🌐 | `journalctl -u caddy -n 50` и `tail -f /var/log/caddy/access.log` |
| Журнал туннеля | 🪟 | `Get-Content C:\mesNation\logs\tunnel.log -Tail 30` |
| Перезапуск туннеля | 🪟 | `Restart-Service OffixTunnel` |
| Общая диагностика | 🪟 | `powershell -ExecutionPolicy Bypass -File deploy\windows\diagnose.ps1` |

- Обновления безопасности на VPS ставятся сами; если нужна перезагрузка — в 04:30, около минуты.
- Сертификаты продлевает Caddy сам.
- Если туннель оборвался (перезагрузка роутера, сбой связи), служба `OffixTunnel` подключается
  заново сама в течение минуты; пока связи нет, пользователи видят страницу «Сервер компании
  временно недоступен», а приложение — понятную ошибку.
- Из офиса нужен исходящий доступ на `<IP>:22`. Если корпоративный фаервол режет исходящие
  подключения — разрешите этот адрес и порт.

## Безопасность — что открыто наружу

| Где | Порт | Зачем |
|---|---|---|
| VPS | 80, 443 | сайт и API (80 — только для выпуска сертификатов и перенаправления на HTTPS) |
| VPS | 22 | SSH: вход администратора по ключу и туннель из офиса |
| Офис | — | **ничего**: туннель — исходящее соединение |

Ключ туннеля на VPS ограничен: без командной строки, без доступа к файлам, только проброс
на 127.0.0.1:15000. Если ключ офиса утечёт, через него нельзя войти на VPS или в офисную сеть.
Новый ключ — повторный запуск `install-tunnel.ps1` после удаления `C:\offix-tunnel\id_ed25519*`
и команда `offix-allow-office` на VPS (старый ключ при этом перестаёт работать).
