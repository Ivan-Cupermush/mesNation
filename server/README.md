# Offix — сервер

Express 5 + PostgreSQL + Socket.IO. TypeScript.

## Запуск

```bash
cp .env.example .env      # заполнить DB_* и JWT_SECRET (openssl rand -hex 48)
npm ci
npm run migrate           # привести схему БД к актуальной версии
npm run dev               # разработка (перезапуск при изменениях)
# прод:
npm run build && npm start
```

Миграции применяются и автоматически при старте сервера.

## Структура

```
src/
  app.ts                 сборка Express-приложения (middleware, роуты)
  index.ts               запуск: миграции → HTTP → Socket.IO
  config/env.ts          переменные окружения с проверкой (zod)
  db/pool.ts             единый пул PostgreSQL + withTransaction()
  db/migrate.ts          раннер миграций (таблица schema_migrations)
  db/migrations/         NNNN_*.sql — новые миграции; legacy/ — история до раннера
  lib/                   логгер (pino), ошибки, валидация, загрузка файлов
  middleware/auth.ts     JWT, проверка активности пользователя, requireDirector
  realtime/socket.ts     Socket.IO с авторизацией по токену
  services/access.ts     ВСЯ модель прав: иерархия ролей, доступ к чатам и задачам
  services/messages.ts   создание сообщений (одно место для сокета, файлов, пересылки)
  routes/                HTTP-эндпоинты по модулям
tests/                   интеграционные тесты (vitest + supertest + socket.io-client)
```

## Модель прав (коротко)

- Директор — пользователь в **корневом узле** дерева ролей (имя узла не важно).
- Задачу можно поставить: себе, всем в своём поддереве, людям **на той же глубине** дерева
  (коллеги своего уровня, даже из другого отдела). Вверх — нельзя.
- Руководитель видит задачи подчинённых (фильтр `team`).
- Чат: всё доступно только участникам. Создатель может всё, администратор — выданные права,
  обычный участник — всё, кроме назначения администраторов.
- Сотрудников не удаляют, а деактивируют: нет входа, нет в списках выбора, история сохраняется.

## Миграции

Не редактируйте применённые файлы — создайте новый `NNNN_описание.sql`.
Пишите их идемпотентными (`IF NOT EXISTS`), чтобы они были безопасны для любой базы.

## Тесты

Нужна отдельная пустая БД — тесты её **полностью пересоздают**
(имя базы обязано содержать `test` или `ci`):

```bash
DB_NAME=mesnation_test JWT_SECRET=... npm test
```

## Логи

JSON-логи pino (в разработке — читаемые). У каждого запроса есть `X-Request-Id`;
пароли и токены в логи не попадают.

## Безопасность

- Пароли — только bcrypt-хеш (cost 12), минимум 8 символов, частые пароли отклоняются.
  Проверка при входе одинаково долгая для существующих и несуществующих логинов.
- Лимиты неудачных входов: 10 за 15 минут с одного адреса и 20 за 15 минут на одну учётную запись.
- JWT (HS256) с версией сессии: смена/сброс пароля, деактивация и «Выйти на всех устройствах»
  (`POST /api/auth/logout-all`) мгновенно отзывают все ранее выданные токены, сокеты рвутся.
- Журнал событий безопасности — таблица `audit_log` (входы, неудачные входы, сброс паролей,
  смена ролей, деактивация, переименование компании).
- Файлы чатов, задач и заметок отдаются только тем, у кого есть доступ; ссылки для внешних
  приложений подписаны и живут 10 минут.
- Мобильное приложение хранит токен в Android Keystore / iOS Keychain и работает только по HTTPS.
